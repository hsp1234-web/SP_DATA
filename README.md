# 智能型期交所數據整合管道 (Intelligent Taifex Data Integration Pipeline)

## 1. 專案簡介

### 1.1 核心痛點

本專案旨在解決在處理台灣期貨交易所（Taifex）提供的歷史數據時所面臨的核心挑戰：**面對期交所格式繁多、結構不一（每日行情、三大法人、選擇權相關報表、各類CSV、ZIP、甚至是內嵌多層ZIP的壓縮檔）、且時常混雜在大量壓縮檔中的海量歷史數據時，傳統手動整理方式不僅效率低下，更容易引入錯誤，嚴重阻礙了後續的數據分析與應用。**

### 1.2 願景

本專案的最終目標是打造一個「**全自動、高效率、可信賴的數據探勘與初步整合解決方案**」。透過本管道，使用者可以快速、安全地對其 Google Drive 中的大量期交所原始數據進行深度探勘，自動化處理巢狀壓縮檔，並為每個檔案（包括壓縮檔本身及內部成員）產生一份包含**檔案元數據（大小、修改時間）、偵測編碼及內容預覽的詳細報告**。

長遠來看，此管道的產出（特別是探勘報告和未來加入的結構化數據輸出）旨在為後續更複雜的量化分析、交易策略回測、以及 AI/ML 模型訓練，提供一個「**清晰、可追溯、初步標準化的數據概覽，為建立單一事實數據源 (Single Source of Truth) 打下堅實基礎。**」

## 2. 功能特性

*   **智慧探勘與深度巢狀處理**:
    *   自動掃描指定 Google Drive 資料夾下的所有檔案及子目錄。
    *   不僅處理頂層的 `.zip` 檔，更能**遞迴地處理 ZIP 中可能包含的其他 ZIP 檔**，確保任何深藏的數據都不會遺漏。
    *   為 ZIP 檔案本身及其內部每一個成員檔案分別產生探勘報告。
*   **絕對安全與高效能**:
    *   採用「串流讀取」及限制預覽內容大小的機制，面對超大檔案（GB級別）也**無記憶體崩潰風險**。
    *   自動啟用所有可用的 CPU 核心進行**平行處理**，大幅提升大規模檔案探勘的效率。
*   **詳盡的即時與總結報告**:
    *   **即時報告**: 針對每個被探勘的檔案（無論是普通檔案還是ZIP內的成員），提供包含檔案路徑、探勘時間、檔案大小、最後修改時間、成功偵測到的編碼（如 ms950, utf-8, utf-8-sig）以及前五行內容預覽的詳細報告。
    *   **終極總結報告**: 任務結束時，生成一份百科全書式的任務總結，包含：
        *   任務概覽（總耗時、掃描目錄數、處理檔案總數等）。
        *   檔案類型統計（例如：`.csv`, `.zip`, `.rpt` 各有多少個）。
        *   編碼分佈統計（例如：`ms950` 和 `utf-8` 各佔多少比例）。
        *   完整的成功探勘檔案清單。
        *   完整的失敗/跳過檔案清單及其原因。
*   **錯誤容忍性**:
    *   在處理一個大型 ZIP 檔時，即使其中**某個成員檔案因格式問題或損壞而解碼失敗，也不會中斷整個流程**。系統會記錄該單一檔案的失敗原因，並繼續處理 ZIP 中的其餘檔案及後續的其他任務。
*   **二進位檔案的智慧識別**:
    *   腳本能夠識別內容無法按常見文字編碼（ms950, utf-8）解碼的檔案（例如 `.sqlite`, `.duckdb`, `.ods`, `.exe`, 圖像檔案等），並在報告中將其標註為「未能使用常見編碼解碼，可能為二進位檔案」，從而優雅地跳過，避免因嘗試解碼而出錯。

## 3. 環境設定

本腳本**專為 Google Colab 環境優化**，並依賴於 Google Drive 進行檔案存取。

*   **必要套件**: 腳本會自動處理 `pytz` 等 Python 標準函式庫以外的依賴（如果有）。使用者通常無需手動安裝。
*   **Google Drive**: 您需要擁有一個 Google 帳戶，並使用其 Google Drive 服務來存放您的期交所數據。

## 4. 如何執行

請依照以下步驟在 Google Colab 中執行本探勘管道：

1.  **準備資料**:
    *   在您的 Google Drive `MyDrive` 根目錄下，建立一個主資料夾（例如，您可以將其命名為 `MyTaifexData` 或任何您喜歡的名稱）。
    *   在您剛剛建立的主資料夾內，再建立一個名為 `01_input_files` 的子資料夾。
    *   將所有從期交所下載的原始數據檔案（通常是 `.zip` 格式，也可能是 `.csv`, `.rpt`, `.txt` 等）**全部放入這個 `01_input_files` 子資料夾內**。您可以依照年份或月份在 `01_input_files` 內再建立更多層的子目錄來組織檔案，本腳本會遞迴掃描。

2.  **開啟 Colab 腳本並設定路徑**:
    *   打開本 `SmartTaifexProspector.ipynb` Colab 腳本。
    *   找到第一個標有「**步驟 1: 📂 設定探勘目標**」的程式碼儲存格。
    *   在該儲存格中，您會看到一行程式碼：`target_folder_path = "MyTaifexDataProject"`。
    *   **這是您唯一需要修改的地方**：請將 `"MyTaifexDataProject"` 這個字串，替換為您在**步驟 1.1** 中建立的**主資料夾的實際名稱**。例如，如果您當時建立的主資料夾名稱是 `MyTaifexData`，則修改後的程式碼應為 `target_folder_path = "MyTaifexData"`。

3.  **依序執行儲存格**:
    *   **非常重要**: 請務必從 Colab 筆記本的**最頂部開始，由上到下，依序執行每一個程式碼儲存格**。
    *   您可以點擊每個儲存格左側的「播放」按鈕，或使用快捷鍵（如 Shift+Enter）來執行。
    *   請確保先執行完「**步驟 1**」的設定，然後再執行「**步驟 2: 🛠️ 核心函式庫與功能定義**」的儲存格。此儲存格包含了所有核心功能的程式碼，必須先執行。
    *   最後，執行「**步驟 3: ▶️ 執行探勘任務**」的儲存格來啟動完整的探勘流程。

4.  **Google Drive 授權**:
    *   當您執行到包含 `drive.mount('/content/drive', force_remount=True)` 的儲存格時（通常在「步驟 3」的開頭部分），Colab 會請求存取您 Google Drive 檔案的權限。
    *   此時會彈出一個授權視窗或顯示一個授權連結。請按照提示，選擇您的 Google 帳戶並點擊「允許 (Allow)」，以完成授權。這是 Colab 腳本讀取您雲端硬碟中數據的必要步驟。

5.  **查看結果**:
    *   探勘任務開始後，您會在「步驟 3」儲存格的輸出區域即時看到每個檔案的探勘報告。
    *   任務全部完成後，一份非常詳細的「任務總結報告」將會顯示在最後。

## 5. 報告解讀

### 5.1 即時報告 (個別檔案報告)

在探勘過程中，每處理一個檔案（或ZIP內的成員檔案），系統都會輸出一份如下格式的即時報告：

```
----------------------------------------------------------------------
✅ [報告]
  檔案路徑: /content/drive/MyDrive/MyTaifexData/01_input_files/OptionsDaily_2023_10_26.csv
  探勘時間: 2023-10-27 10:30:00
  檔案大小: 1.25 MB
  最後修改: 2023-10-26 14:00:00
  偵測編碼: ms950
  內容預覽 (前五行):
    L1: ' 成交日期,商品代號,履約價格,到期月份(週別),買賣權別,成交時間,成交價格,成交數量(B or S),開盤集合競價 \r\n'
    L2: '20231026,TXO,16000,202311W1,C,084501,30.5,10, \r\n'
    ...
----------------------------------------------------------------------
```

*   **狀態圖示**: ✅ 代表成功探勘，❌ 代表探勘過程中發生錯誤。
*   **檔案路徑**: 指向被探勘檔案在 Google Drive 中的完整路徑，或其在 ZIP 檔中的相對路徑。
*   **探勘時間**: 本次探勘執行的時間。
*   **檔案大小**: 人類可讀的檔案大小。
*   **最後修改**: 檔案在 Google Drive 中記錄的最後修改時間（台北時區）。
*   **偵測編碼**: 系統成功識別並用於解碼預覽內容的檔案編碼。若為二進位檔案或解碼失敗，此處可能顯示錯誤訊息。
*   **內容預覽**: 檔案的前五行內容。若檔案為空，則顯示 `(檔案為空)`。若解碼失敗，則不顯示此部分。

對於 `.zip` 檔案本身，會有一份特殊的摘要報告：
```
----------------------------------------------------------------------
✅ [報告]
  檔案路徑: /content/drive/MyDrive/MyTaifexData/01_input_files/TXF_Options_Daily_2023.zip
  探勘時間: 2023-10-27 10:32:00
  檔案大小: 150.7 MB
  最後修改: 2023-10-01 08:00:00
  內含檔案: 250 個
----------------------------------------------------------------------
```

### 5.2 最終總結報告

所有檔案探勘完畢後，系統會輸出結構化的總結報告：

*   **任務概覽**:
    *   `總運作時間`: 整個探勘任務的耗時。
    *   `掃描目錄總數`: 遞迴掃描的子目錄數量。
    *   `處理頂層檔案/壓縮包`: 在 `01_input_files` (或指定目標) 下直接找到的檔案和ZIP包的數量。
    *   `最終探勘檔案總數`: 包括所有ZIP內成員檔案在內的，實際被產生報告的檔案總數。
*   **檔案類型統計**:
    *   列出所有探勘到的檔案的副檔名及其對應的數量。
    *   **用途**: 這份統計能幫助您快速盤點數據資產的**組成複雜度**。例如，大量的 `.csv` 檔案代表後續處理的重點將在於內容清洗；而 `.ods` 或其他二進位檔案的存在，則提醒您可能需要額外的工具來處理它們。
*   **編碼分佈統計**:
    *   列出所有成功解碼檔案的編碼類型及其數量。
    *   **重要性**: 這是一個關鍵的**數據品質健康指標**。如果大部分檔案都是 `ms950`，代表我們在後續的轉換階段，必須將「`ms950` 編碼優先處理」作為核心策略。如果未來 `utf-8` 檔案增多，則證明數據源的品質正在改善或來源多樣化。
*   **成功探勘檔案清單**:
    *   列出所有被成功探勘並生成內容預覽的檔案路徑。
*   **失敗/跳過檔案清單**:
    *   列出所有在探勘過程中遇到問題的檔案路徑及其失敗原因（例如：「未能使用常見編碼解碼，可能為二進位檔案」或「處理ZIP檔案時發生錯誤」）。
    *   **可操作性**: 這份清單不是單純的錯誤報告，而是一份「**待辦事項**」。您可以根據清單中的失敗原因，來決定後續是應該為它開發新的解析器（如果它是重要的未知文字格式），還是將其歸檔忽略（如果是無關的二進位檔案），或是檢查檔案是否已損壞。
